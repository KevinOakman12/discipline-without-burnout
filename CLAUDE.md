# day_done — правила для Claude

## Обязательное тестирование после каждого изменения

После КАЖДОГО изменения кода Claude обязан самостоятельно провести тестирование:

1. **Статический анализ** — проверить изменённые файлы на очевидные ошибки: синтаксис, импорты, типы пропсов, CSS-селекторы
2. **Логика** — трассировать ключевые сценарии вручную (например, алгоритм streak с разными входными данными)
3. **Регрессии** — проверить, что исправление одной проблемы не сломало другую
4. **CSS** — убедиться, что новые токены используются корректно, нет опечаток в переменных, нет дублирующихся правил
5. **Граничные случаи** — проверить edge-cases (пустое состояние, удалённые привычки, тёмная тема)

**Тестирование проводится ДО отправки ответа пользователю.**

## Стек

- Preact (через esm.sh, без сборки)
- Vanilla CSS с custom properties
- localStorage для хранения данных
- Telegram Mini App (WebApp SDK)

## Архитектура

- `src/store/storage.js` — единственный источник истины, localStorage
- `src/utils/streak.js` — чистая логика серий, currentStreak НИКОГДА не хранится
- `src/App.js` — главный роутер и оркестратор состояния
- `styles/tokens.css` → `base.css` → `components.css` → `screens.css` — каскад стилей

## Ключевые инварианты

- `currentStreak` вычисляется каждый раз из `completedDates`, никогда не хранится
- Бесплатная защита недели НЕ списывается для текущего дня (он ещё не закончен)
- Зелёная подсветка в календаре — только при `completed > 0`
